# Example Project Brief

## Summary

[Example Company] needs a short onboarding guide for a developer API.

## Goal

New users can create a sample credential placeholder, run one request,
understand the response, and find the next reference page without contacting
support.

## Audience

- Primary audience: external developers
- Secondary audience: support engineers

## Inputs

- Existing API reference
- Sample request and response
- Product manager notes

## Deliverables

- Quickstart guide
- Review checklist

## Constraints

- Timeline: five business days
- Format: Markdown
- Reviewers: engineering and product
- Tools: GitHub pull request

## Risks

| Risk | Mitigation |
| --- | --- |
| Missing sample data | Use placeholders until engineering approves a sample |
| API behavior changes | Confirm against a test endpoint before final delivery |

## Definition Of Done

- Quickstart runs from a clean account
- Reviewer comments are resolved
- Final document links to the API reference
